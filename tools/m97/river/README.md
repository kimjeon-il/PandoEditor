# Chromium-authoritative river checkpoint

The application runs unchanged pinned graph modules through a fresh worker-local
Qt QJSEngine, with the six guarded syntax replacements, finite plain-data globals
and shared polygon-clipping compatibility loader. It installs **no math override**.
Node is test tooling, never an application runtime or a browser golden proxy.
There is no controller, UI, selection-cache or native sliver-preview integration.

## Why the former cosine closure was removed

Actual CI run `37231724016`, commit
`e2eed653099629bc30fa62b2441b4acb3fe7ba4f`, executed official Playwright 1.62.1 /
Chromium 151.0.7922.34 revision 1234. Its 24 real-browser outputs matched Node
24.19.0 on 18 synthetic cases and differed on all six full-country cases. The
browser cosine at 0.7719766168394622 is 0.7165332754286245, matching stock Qt;
Node's older V8 returns 0.7165332754286247. Private diagnosis and the production
regression establish exact stock-Qt equality with all 24 captured browser outputs.

The old Node-specific V8/fdlibm closure, vendor snapshot/license, QObject cosine
bridge, generated target, C++20 requirement and isolated FP flags have therefore
been removed. No replacement approximation, compiler/math flag or geometry/key
waiver was introduced. Original river/planar bytes remain unchanged. The observed
profile is Linux x86_64 Qt 6.8.3 versus that exact browser; other platforms,
compilers, Qt/browser versions and CPUs are not covered by a universal claim.

`tests/fixtures/web-m972-river/browser-baseline.json` is derived from authenticated
actual-browser output, not from Node. It retains source/input/output hashes,
ordered keys/counts, exact CI commit/run/artifact provenance and the old Node
negative evidence. Reproduce it with:

```
node tools/m97/river/capture-browser-baseline.mjs CAPTURED_ARTIFACT_DIRECTORY OUTPUT.json
```

The extractor pins the captured HTML, compressed payload and browser evidence
files before deriving any expected output. Raw geometry remains in CI artifacts;
only compact hashes/identities are committed. V8 15.1.206.8 / commit
`f479186c16abdb6fa05539fe957bb84deee830df` is pinned from Chromium's official DEPS
and version header. The original artifact did not record CDP's jsVersion; the
new job records it and requires the exact runtime version.

## Production worker and presentation boundary

`calculateRiverPartitions` accepts owned typed donors/source features/base
components and explicit fixture or live-coordinate revisions. Actual JS
JSON.stringify creates live donor/edit signatures. Original module defaults,
algorithm revision, graph calculation, keys and composition remain authoritative.
No QObject or QJSValue crosses the worker boundary. Strict JSON parsing and
shape checks prevent failed decoding from becoming an empty Completed result.
Cancellation wins over errors, discards all raw/presentation/diagnostic outputs,
and is cooperative around synchronous JS work. The GUI thread must not call it.

Raw `candidates`, `components` and `json` remain unchanged by presentation.
Separately returned `presentationCandidates`, `presentationComponents` and
`presentationJson` execute the pinned original polygon normalizer after raw key
creation, filter null geometry/missing donor, then call original composition
again with the corresponding candidate set. Original base components remain
originals. `workspaceJson` is bounded diagnostic data through the original
workspace exporter; it does not participate in geometry or key generation.

Original hashes remain runtime guarded; `generate-adapters.py --check` verifies
checked-in deterministic six-expression adapters and unchanged planar bytes.
The normalizer's original bytes/hash are also guarded. The flatMap/own-data-copy
and structuredClone adapters remain explicitly limited to finite acyclic plain
JSON data and ordinary arrays. LF attributes and a clean `core.autocrlf=true`
checkout regression protect every pinned resource/dependency/fixture.

The previously approved integer microdegree `/1000000.0` conversion remains.
It matches the original decoder's division exactly, including negative,
antimeridian and near-polar values. No packed format, manifest identity or
physical integer cache format changes; existing document geometry is untouched.

## Reproducible inputs and direct runtime comparison

`suite.mjs` freezes one payload containing all 42 cases, exact source/boundary
hashes, original full-country validation context and commit/run identity:

- Original 18 synthetic + six actual SRB/HRV/MDA raw/live requests, unchanged from
  the authenticated browser capture
- Six translated crossing pairs at the demonstrated positive/negative latitudes
- Three gaps around 0.5 m, without fabricated boundary-case output counts
- Three next-representable latitude pairs as the explicitly approved fallback
  for miniature near-collinear fixtures
- Two narrow latitude cases on opposite sides of the actual 1e-6 cosine clamp
- Four full-source feature-order / line-traversal perturbations

Original SRB/HRV/MDA cases additionally run a separate hash-labelled instrumented
browser module at the known first-difference segment pairs (14/732, 589/402,
221/67). It records actual projected edges/IDs/intersection hits and requires
near-collinear arithmetic. Every instrumented complete output must equal that
case's uninstrumented browser output. These are diagnostic observations, not
rewritten production modules or invented mini-case coverage. Metamorphic results
for real-source perturbations are reported, not assumed universally invariant.

The native job preserves the existing full CTest gate and skip audit. Required
river tests check the captured actual-browser baselines, current-provider shared
source IDs/full geometry, raw/live modes, repeated requests/cache stability and
real cancellation. Node output is retained only as a labelled diagnostic.

CTest artifacts include exact executable SHA, run/commit, case hashes and output
file hash. `collect-native.mjs` reuses those already-calculated 24 observations
only after verifying the receipt and exact executable, and executes the remaining
18 stress cases through the compiled production calculator. Missing evidence or
mismatched receipts fail. It publishes one payload/native artifact for the same
run/commit. The dependent browser job downloads that artifact, checks all source
and input identities, and executes the original modules in official Chromium.
No local browser retry, alternate executable, math flag or external hosting is
used. Original static imports are only redirected to verified sibling Blob URLs.

`compare-browser-native.mjs` requires exactly 42 ordered observations, 42 actual
presentations and 42 workspace traces on both sides. It compares complete raw
and presentation outputs and provenance exactly, with computeMs as the sole raw
exclusion. It validates runtime/source/commit/run/input identities and fails
missing, reordered or truncated evidence. The old 18/24 outcome cannot pass.

original country features. That 12,415,783-byte GeoJSON is separately checked out

Artifacts retain selected identities/geometry/provenance, input transfer/context,
authoritative returned transfer, affected/removed objects, affected before/after
geometry, full-world before/after hashes and admitted sliver count/area. The raw
fixture lane does not stand in for the normalized live-boundary lane. These are
browser worker-oracle observations, not controller execution or completed native
annex/sliver-preview parity. Native D3 remains the next slice.

with its v0.13.0 sibling; `PANDOEDITOR_RIVER_COUNTRIES` is the separately pinned

browser evidence. Generating 42 inputs or running Node preflights does not prove
new Chromium execution. Actual 42-case Chromium presentation/annex results remain
pending until the coordinator publishes the reviewed exact commit and observes
the new CI job passing. Independent review/full native aggregate and publication
remain coordinator-owned; no universal cross-runtime equivalence is claimed.
