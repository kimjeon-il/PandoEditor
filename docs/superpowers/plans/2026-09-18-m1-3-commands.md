# M1.3 Atomic Commands Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to execute the approved design task by task.

**Goal:** Route desktop/mobile edits through one prepare/confirm boundary and one snapshot ChangeSet per confirmed action.

**Architecture:** Immutable, heap-stable document states own their indexes and CountryViews. A move-only preview owns validated before/after states; Project swaps complete states only after history allocation succeeds. Domain rules live in commands.cpp, not QML or controller branches.

**Tech Stack:** C++17, Qt >=6.5, CMake/CTest; GitHub validation uses Qt 6.8.3.

**Spec:** `docs/web-to-qt-roadmap.md` M1.3 and the user-approved design, including reference rebuilding, composite atomicity, independent dirty/revision and single-use previews.

## Global constraints

- Base main: `6ae7d807bd54dd27cca4a8d2c530340ec25601b5`; never write main.
- All project mutation is serialized on the editor thread. Worker/session scheduling is M1.4, not part of this change.
- Invalid/cancelled/stale/NoOp requests do not change document, saved baseline, revision, Undo or Redo.
- Successful confirm/Undo/Redo increments revision once; saving does not. Reopening creates a fresh instance identity.
- Keep immutable geometry sharing and exact retained payloads; no new geometry/domain editing commands.
- Preserve legacy Project editing methods as compatibility adapters to the same processor.
- Reject Undo/Redo while unapplied drafts exist; preserve drafts and Redo and offer explicit Apply/Cancel.
- Actual Android input and Windows-native runtime results must not be inferred from Linux/offscreen tests.
