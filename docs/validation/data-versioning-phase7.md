# 데이터 버전 관리 7단계 — 공개 배포 URL·기존 앱 릴리스·전체 브랜치 보관 안전성

## 1. 범위와 결론

- 구현 브랜치: 웹 `kimjeon-il/Pando`의 `work/gis`. 앱은 기존 구현·내장 자산을 변경하지 않았다.
- 고정 검증 증거: [Stage 7 GitHub Actions #37822762630](https://github.com/kimjeon-il/Pando/actions/runs/37822762630) **성공**. 데이터 검증·단위검사 **15/15 통과**.
- 실데이터 검증 결과: 웹 **7개 브랜치**, 앱 **5개 브랜치**, 앱 GitHub Releases **23개**를 조사. 원본 참조 검사의 미해결 오류 0건.
- **보관 후보 26개 버전 그룹·2,124개 파일·564,189,000 bytes 전부에서 공개 URL의 대표 파일 응답 확인**.
- **삭제 승인된 파일 0개**. URL 보존이 확인되지 않은 삭제·이름 변경·재압축·배포 설정 변경은 진행하지 않았다.

## 2. 실제 GitHub Pages 배포 구조

GitHub Pages API에서 다음 설정을 확인했다.

| 항목 | 확인 값 |
| --- | --- |
| 사이트 주소 | https://kimjeon-il.github.io/Pando/ |
| 배포 소스 | **main 브랜치, 저장소 루트 `/`** |
| 배포 방식 | GitHub Pages `legacy` |
| 배포 상태 | `built` |
| 사이트 루트 HTTP 검사 | 200, 판도편집기 HTML 확인 |
| 구 명칭 후보 `/world-map/` | HTTP 404 (현재 공식 배포 주소가 아님) |

웹 `main`과 다수의 `work/*` 브랜치는 `world-preview-v0.36.0.json`을 읽는 **버전별 로더**를 사용하며, `work/gis`에서 도입한 `world/current.json` 불변 번들 구조로 일괄 전환되지 않았다. 따라서 GIS 작업 브랜치에서 사용하지 않는다는 이유만으로 웹사이트 배포 자산에서 제거할 수 없다.

## 3. 기존 공개 경로 검증

- GitHub Pages 설정에서 제공한 **검증된 실제 사이트 주소**를 기준으로 구버전 자산에 대해 **HTTP HEAD 표본 검사**를 수행했다.
- 수계·지형 구버전은 매니페스트와 대표 인덱스/타일 등을, 기타 구버전 지도 데이터는 실제 Git 트리에서 존재하는 파일을 선정했다.
- 보관 후보 **26개 그룹 전부에 대해 공개 자산 URL 응답이 확인**되어 `retain-public-asset-url`로 분류했다. 이 26개 그룹의 2,124개 파일을 보관 유지 대상으로 취급한다.
- **중요한 검증 경계:** 2,124개 파일 전체의 URL을 각각 GET·SHA-256 검증한 것은 아니다. *그룹별 대표 URL의 도달성*을 확인한 것이다. 사용자가 존재하지 않는다고 증명할 수 없는 외부 링크·캐시·기존 배포본은 안전하다고 추정하지 않는다.
- 공개 URL의 404나 조사 불능 역시 외부 사용자가 없다는 증거가 아니다. 향후 구버전 파일의 원본 삭제에는 명시적 승인과 완전한 배포 경로 보존이 필요하다.

## 4. 앱과 다른 브랜치의 호환성

- 웹 브랜치 7개를 각각 **고정 40자리 Git 커밋의 원본 소스·매니페스트**에서 비교했다. `main` 등 기존 버전별 로더와 `work/gis` SHA 번들을 구별했다.
- 앱 브랜치 5개의 데이터 계약을 확인했다. `main` 등은 `assets/world/manifest.json` **v1**, `work/gis`는 출처가 명시된 **v2**다.
- 앱 v1의 고정 자산 경로와 v2의 `source.path`를 각각 원본 웹 Git Blob에 대조했으며 검사 중 원본 소실·해시 불일치 **0건**.
- 앱 GitHub Releases **23개** 확인. 이 가운데 과거 Windows 미리보기나 소스 릴리스가 포함될 수 있으나, **배포 ZIP·EXE를 다운로드·역분석하지 않았다**. 따라서 과거 앱 배포본과 이력 파일 간의 모든 의존성이 완전히 해소됐다고 간주하지 않는다.

## 6. 다음 이관 방식 — 기존 URL 유지가 전제

1. **공개 자산 분리 설계:** 현재 URL `/Pando/assets/data/...`를 유지하면서, 과거 자산을 **고정 Git 커밋에서 배포 산출물에 다시 주입하는 GitHub Pages Actions 배포** 또는 동등한 고정 경로 호스팅으로 전환하는 안을 우선 검토한다. 아직 Pages 소스·배포 구성을 바꾸지 않았다.
2. **정본 감사·복원 증거:** 원본 추적 경로·Blob SHA·크기·역사적 Git 커밋·기존 Pages URL을 그룹별로 고정한다. 구버전 매니페스트 자체에 남은 불일치 7건은 별도 표기하고 임의 교정하지 않는다.
3. **삭제 전 릴리스 게이트:** 실제 배포 변경 전후 **전체 2,124개 파일 URL 및 원본 바이트 무결성**, 현행 지도·수계·지형·브라우저 캐시, 앱 릴리스 및 저장/Undo 계약의 범위별 회귀를 검증한다. 대상이 대용량이므로 검증 절차는 별도 구현이 필요하다.
4. **승인 후 정리:** 위 배포 경로 보존이 확인된 후에만 사용자가 명시적으로 승인한 버전 그룹을 소스 트리에서 순차적으로 제거한다. 배포본 검증 실패 시 기존 Pages 게시 구조를 유지하거나 즉시 복귀한다.
