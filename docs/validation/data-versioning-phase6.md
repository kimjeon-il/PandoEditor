# 데이터 버전 관리 6단계 — GIS 구버전 자산 참조 감사·보관 대상 확정

- 작업 범위: 웹 kimjeon-il/Pando의 work/gis, 앱 kimjeon-il/PandoEditor의 고정 출처 교차검증.
- 기준 웹 Git 커밋: 7924fcda8afa171735b7f5914a2f9f77e7a6809c (코드·검증기 기준).
- 실제 완료된 검사: [Web GIS Legacy Assets Stage 6 Gate #37820208955](https://github.com/kimjeon-il/Pando/actions/runs/37820208955).
- 추가 파일: 웹 tools/audit-legacy-gis-assets.mjs, tests/unit/legacy-gis-assets-audit.test.mjs 및 .github/workflows/legacy-gis-stage6-gate.yml.
- **기존 국가·수계·지형·역사 라이브러리 자산의 바이트는 변경하지 않았다.** 파일 제거·재압축·배포·main 제품 코드 병합도 수행하지 않았다.

## 1. 검증 방식 및 범위

GitHub API의 정확한 고정 커밋 트리를 읽어 assets/data 이하 **3,101개, 총 1,154,121,426 bytes**의 경로·Git Blob SHA·크기를 조사했다. 대량의 구형 WebP·수계 바이너리를 다운로드하거나 열지 않았다.

- Node 단위검사 **7/7 통과**, 현행 실행·생성·앱 출처 의존 파일의 경로/크기/Blob 오류 **0건**.
- 실사용 코드·검증기·워크플로 등 **939개 소스 파일**의 정적 참조 검사. 정의된 검사 대상 중 체크아웃 누락 0개.
- 현재 지형 v0.12.6 매니페스트에서 334개 타일 경로를 생성해 Git 트리와 대조.
- 현재 수계 v0.13.1이 구형 v0.13.0의 인덱스·상세 메타데이터·shard 3개를 참조하므로 보호.
- 현행 world/current.json의 5개 SHA 주소 자산, 현재 빌드에 필요한 world-preview-v0.36.0.json과 그 입력 파일, 공유 경계 캐시도 보호.
- 앱 고정 매니페스트의 source.path 7개를 웹 Blob과 대조해 **7/7 동일**.
- 동일 Git Blob 71개 중복 그룹을 확인. 파일 복사본의 명목상 중복 크기는 **101,453,860 bytes**이지만 Git은 동일 Blob을 내부적으로 이미 공유한다.

- 위 보관 검토 후보는 26개 버전 그룹이다. 해당 코드·테스트 범위에서 직접 긍정적인 사용 참조가 발견되지 않았다는 뜻이지, 기존 배포 링크와 외부 의존성이 없다는 확증은 아니다.
- 별도 **활성/앱 고정 자산 12개 버전 그룹(357개 파일)**과 **테스트가 직접 참조하는 3개 그룹(3개 파일)**은 유지 대상으로 분류했다.
- 전체 데이터에서 직접 보호해야 하는 실행·생성·앱 출처 경로는 363개다. 국가 원본, 계보, 지명 등 다른 데이터는 정리 대상에 넣지 않았다.
- Git에서 파일을 지워도 이미 저장된 Git 객체 전체가 동일 크기만큼 줄어드는 것은 아니며, 외부 URL 접근성이 그대로 유지되는 것도 아니다.
- CI의 이전 제외 규칙 중 '!/assets/data/...'처럼 구버전을 제외하는 행위는 실사용 참조로 계산하지 않는다.

## 3. 역사적 매니페스트의 기존 불일치 7건

- 이전 세계지도 매니페스트 v0.30.0–v0.34.0 중 5건은 추적되지 않는 countries-ne-5.1.1.geojson.gz 파일을 지목했다.
- 이전 매니페스트 v0.30.0 및 v0.31.0에서는 world-mesh-v0.12.6.bin.gz 파일 크기를 14,626,436 bytes로 기록했지만 현재 추적본은 14,619,043 bytes였다.
- 과거 매니페스트의 재현성 경고이며 **현재 실행 계약 오류 0건과 별도로 관리한다.** 과거 메타데이터를 현재 데이터에 맞춰 임의 교정하지 않았다.

## 4. 남은 검증 및 정리 조건

- 위 보관 후보를 실제로 지우려면 외부 공개 링크와 과거 배포본 참조, 역사적 재현성, 테스트 fixture, 타 저장소 의존성을 추가 검토해야 한다. 삭제 대상 확정과 검증 전 임의 정리는 금지한다.
- 구버전 정리 작업 전에 정확한 삭제 전 Git 커밋 SHA와 개별 파일의 분류를 기록하고, 범위를 승인받아 **버전 그룹 단위**로 수행한다.
- 5단계 보강 CI [#37817249950](https://github.com/kimjeon-il/PandoEditor/actions/runs/37817249950)에서 네이티브 역사 카탈로그 테스트는 성공했으나 편집 컨트롤러 검사 30개 중 4개가 실패했다. 이 미해결 Qt 검사 문제를 6단계 GIS 감사 성공으로 덮어 쓰지 않는다.
- 6단계는 **참조 조사·자동 감사·대상 분류**까지 완료했다. 자산 정리·기존 URL 차단·제품 병합·배포는 수행하지 않았다.

## 5. 브랜치 정책

구현 스크립트·검증 워크플로는 웹 work/gis에만 유지한다. 본 보고서는 웹·앱 각 work/gis에 보관하고, 두 저장소의 모든 현존 브랜치에는 공통 진행 기록 문서만 동일하게 동기화한다. work/* → main 제품 코드 병합 및 로컬 상설 워크트리 삭제는 하지 않는다.
