## 남은 데이터·저장 정책 차이

앱은 번들 과거 라이브러리 **25개를 시작 시 자동 설치**한다. 파일 기반으로만 로드한다는 이전 설명은 잘못됐다. 웹 과거 라이브러리는 26개이며 앱에는 `historical-country:north-schleswig`가 없다. 양쪽 기존 항목 모두 기본 국기 metadata를 갖는다.

웹은 고정 현재 세계 국가 카탈로그를 과거 라이브러리와 함께 보여준다. 앱의 과거 항목 실체화는 현재 프로젝트 국가 도형을 참조하므로 국가를 삭제한 프로젝트에서는 일부 경계가 누락될 수 있다. 앱은 현재 국가 카탈로그 전체를 같은 과거 추가 목록에 넣지 않으며 기존 국기 번들 258개는 국기 선택 모드에서 유지한다. 데이터 전체 교체나 실체화 로딩 정책 확대는 이번 UI 범위에서 수행하지 않았다. 이를 맞추려면 북슐레스비히 데이터와 고정 현재 국가 카탈로그를 추가하고 현재 프로젝트 의존성을 변경해야 하며, 패키지 크기·경계 출처·추가 트랜잭션 회귀를 별도로 검증해야 한다.

국가 메모의 공백은 그대로 저장한다. 하위 단위·지방 메모는 기존 엔진의 앞뒤 공백 정리를 유지한다. GIS·기하 엔진과 영토 분할/편입 계산 규칙 전체를 웹과 동일하게 변경한 작업은 아니다. OS 파일 선택창은 기존 플랫폼 기능을 사용한다.

## 검증과 배포 기록

등록 테스트는 실제 `ctest --show-only=json-v1`에서 **114개**다. 이전 109개 실행은 `ui_tests`, `world_corpus_tests`, `world_projection_diagnostics`, `builtin_world_policy_tests`, `hydro_full_dataset_tests`의 명시적 제외 결과였다. QTest 개별 사례 수를 CTest 수에 합산하지 않는다.

최종 소스 검증과 Windows preview 배포의 정확한 결과는 아래에 확정 기록한다. 전체 플랫폼 release gate의 기존 `BLOCKED` 상태를 이번 Windows UI preview 성공으로 대체하지 않는다. 장시간 GPU 부하 테스트와 PC/커널 강제 종료 원인 분석은 수행하지 않는다.
최신 웹 `a87f4d2` / 배포 `8b5f72e`의 통합 객체 이행은 별도 모델 변경이다. 앱의 `CreateTerritorialIntent`는 국가/하위 단위/지방을 구별하고 하위 단위 생성 시 소속 국가·상위 단위를 요구한다. `beginTypeConversion()`은 원본 종류를 실제 변경하며 독립권역 복사 API가 아니다. 일반 객체의 시작/종료일 변경도 현재 region 전용 저장 규칙과 다르다. 따라서 단일 객체 생성+임의 parent, 독립권역 체크, 일반 parent 편집, 원본·잠금을 보존하는 독립 복사, topology/Worker 및 그룹 분류 이행은 이번 UI preview에서 구현하지 않았다. 기존 변환을 복사로 위장하지 않았다. 이를 완료하려면 문서 schema·관계/소유권 규칙·트랜잭션/undo와 GIS·라이브러리 호환 마이그레이션이 필요하다. 최신 웹 자체의 해당 이행/테스트도 미완이며, 본 배포를 최신 통합 객체 모델과 완전히 같다고 표시하지 않는다.
